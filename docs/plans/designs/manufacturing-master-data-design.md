# Manufacturing Master Data Design Draft

> 来源：`mes-service` 设计线程派生草稿。本文不是稳定真相源，用于给后续主数据线程提供恢复入口。

## 1. 目标

- 冻结 `mes-service` 所依赖的最小产品/制造主数据边界。
- 明确模具与产品、制造规格、在制品之间的关联方式。
- 避免把“销售 SKU”误当成“制造过程中的在制品表达”。

## 2. 当前判断

- 不应直接把“独立产品主数据服务”视为默认正确答案。
- 更合理的当前表述是：OES 需要冻结 `product + manufacturing master data` 边界，但服务化形态仍可后定。
- `mes-service` 第一阶段不能自己长期拥有产品主数据真相，否则后续会在模具、工艺、质量、销售协同处失控。

## 3. 推荐对象分层

### 3.1 `Product Family / SPU`

- 表达相对稳定的产品家族或产品族。
- 适合承载：
  - 基础产品身份
  - 大类目与系列
  - 面向经营与产品线的长期稳定语义
- 不足以单独表达制造差异。

### 3.2 `Manufacturing Spec`

- 表达“会影响制造路线、模具适配、工序参数、质检规则”的制造规格。
- 它不应直接等同销售 SKU。
- 典型属性包括：
  - 洗手盆：单孔 / 三孔、三孔四寸 / 三孔八寸
  - 马桶：300 / 400 排污孔
  - 需要的工艺路线分支
  - 是否需要二次花纸烧制
- `Mold Definition`、工艺路线、打孔规则、关键工序参数更适合强关联到 `Manufacturing Spec`。

### 3.3 `Wip Attribute Snapshot`

- 表达“当前在制品已经锁定了哪些制造属性、还有哪些属性尚未锁定”。
- 这是在制品状态，不是主数据模板。
- 建议字段：
  - `productFamilyRef`
  - `resolvedAttributes`
  - `pendingAttributes`
  - `currentStep`
  - `currentRouteRef`

## 4. 为什么 `Manufacturing Spec` 不能直接等于在制品

- `Manufacturing Spec` 更适合表示“可制造配置模板”。
- 在制品会处于“部分属性已确定、部分属性还未承诺”的中间状态。
- 因此在制品必须有自己的属性快照，而不是直接被迫绑定到一个完整最终 SKU。

## 5. 在制品表示建议

### 5.1 A 洗手盆未打孔前的胚体

- `productFamilyRef = A 洗手盆`
- `resolvedAttributes = {}`
- `pendingAttributes = [holePattern, glazeColor]`
- 说明：此时仍是通用前段半成品。

### 5.2 A 洗手盆单孔未喷釉

- `productFamilyRef = A 洗手盆`
- `resolvedAttributes = { holePattern: single }`
- `pendingAttributes = [glazeColor]`
- 说明：结构属性已在前段锁定，但外观属性尚未锁定。

### 5.3 A 洗手盆单孔喷黑色釉

- `productFamilyRef = A 洗手盆`
- `resolvedAttributes = { holePattern: single, glazeColor: black }`
- `pendingAttributes = []`
- 说明：关键制造属性已定型，可映射到更具体的制造配置或销售可供货对象。

### 5.4 A 洗手盆单孔喷白色釉

- `productFamilyRef = A 洗手盆`
- `resolvedAttributes = { holePattern: single, glazeColor: white }`
- `pendingAttributes = []`

## 6. 模具关联建议

- 模具不应只关联 `SPU`，否则粒度过粗。
- 建议：
  - 主归属可关联到 `Product Family / SPU`
  - 适配范围必须能表达 `Manufacturing Spec`
- 这样才能支持：
  - 同一产品族下不同孔位/开孔方案
  - 不同模具只适配某些制造规格
  - 按模具寿命、供应商、批次回溯到具体制造规格

## 6.1 模具分类维度

模具不应只有单一“类型”字段，至少应支持多维分类：

- 材料维度：
  - 树脂模具
  - 石膏模具
- 功能维度：
  - 母模
  - 生产模具
- 生产方式维度：
  - 高压机模具
  - 上线模具
  - 立交上线模具
  - 地摊模具
- 产出结构维度：
  - 单模具
  - 双胞胎模具
  - 多胞胎模具
- 组合结构维度：
  - 单款模具
  - 多款/多组件组合模具

这意味着模具建模应避免把“模具类型”做成单枚举字段，而应支持多标签或多维属性。

## 6.2 母模与生产模具

- 母模应视为资产。
- 生产模具同样应视为资产，因为它同样具有：
  - 编号
  - 寿命
  - 当前状态
  - 供应商来源
  - 维修保养记录
  - 质量表现

二者区别不在于“是否是资产”，而在于资产角色不同：

- 母模：
  - 主要服务于复制/生产生产模具
  - 更偏上游工装资产
- 生产模具：
  - 直接服务现场成型与产出
  - 与在制品追溯、质量回溯、寿命统计直接关联

## 6.3 模具与产线

- 模具不仅关联产品/制造规格，也关联产线适配关系。
- 一条产线需要支持灵活组合不同模具来生产不同款式。
- 某些模具在到场后不能立即投产，需要先烘干、安装、调试、修补，再进入可用状态。

因此模具资产建议至少支持这些现场状态：

- 待烘干
- 待安装
- 安装调试中
- 可用
- 使用中
- 维护中
- 待维修
- 停用
- 已报废

## 6.4 组合式模具与一次产出结构

- 某些高压模具一次可能产出两个款式，或多个组件。
- 某些产品并非单次脱模即得完整成品，而是多个组件脱模后再拼接。

因此模具定义不能假设“一套模具 = 一个款式 = 一个完整件”。

建议补充：

- `outputStructure`
  - 描述一次使用产出多少件、多少组件
- `componentOutputs`
  - 描述每个组件对应什么制造规格或组件定义
- `assemblyHint`
  - 指出后续是否需要拼接/组装工序

这对智能马桶坐头外壳 + 组件拼接场景尤其重要。

## 7. 对 `mes-service` 的直接影响

- `mes-service` 需要消费：
  - `Product Family`
  - `Manufacturing Spec`
  - `Mold Definition`
  - `Route Template`
  - `Step Definition`
- `mes-service` 自己长期拥有的是：
  - `Wip Attribute Snapshot`
  - 模具/泥浆/釉料/窑次的使用事实
- `mes-service` 不应成为：
  - 产品目录真相服务
  - 销售 SKU 真相服务
  - 完整工艺主数据真相服务

## 8. 当前推荐结论

- 不要先假定“独立产品主数据服务”一定正确。
- 先冻结 `product + manufacturing master data` 领域边界。
- 在实现上可先由一个较粗粒度主数据模块或服务承载，再根据证据拆分。

## 9. 建议后续线程要回答的问题

- `Manufacturing Spec` 与销售 SKU 的映射规则是什么？
- 颜色、花纸、logo 这类后段属性是否都进入 `Manufacturing Spec`，还是分层表示？
- 模具、路线、工序参数、质检规则由同一主数据域承载，还是继续拆分？

## 10. 新增判断：`Manufacturing Spec` 与销售 SKU 的关系

- 二者通常应有关联，但不应强行一一相等。
- 更合理的关系是：
  - `Manufacturing Spec`
    - 表达影响制造路线、模具适配、工序参数、前后段承诺点的制造属性
  - `Sales SKU`
    - 表达面向销售、定价、客户下单、交付的经营对象

在很多简单场景下：

- 一个 `Manufacturing Spec` 可能映射一个销售 SKU

但在卫浴陶瓷场景里常见这些情况：

- 前段在制品尚未锁定颜色或后加工时，尚不能映射具体销售 SKU
- 同一制造规格在不同客户质量要求下，可对应不同可销售对象
- 某些后段属性（花纸、logo、客户定制）在制造上是后置承诺，不应强迫前段在制品绑定最终销售 SKU

当前推荐结论：

- `Manufacturing Spec` 与销售 SKU 应建立映射关系，但不要合并为同一对象。

## 11. 材料批次与在制品关联草稿

> 来源：`mes-service` 设计线程。当前只冻结 MES 第一阶段需要的追溯边界，不替代完整材料主数据、配方或实验室体系设计。

### 11.1 当前判断

- 泥浆、釉料、色釉等材料批次会直接影响黑点、裂纹、变形、色差、吸水率、流动性与烧成表现。
- `mes-service` 第一阶段必须记录材料批次与在制品、工序、质检结果之间的使用事实。
- 完整材料主数据、配方管理、实验室标准、供应商材料质量评估不应由 `mes-service` 长期独占。

### 11.2 推荐对象

- `MaterialBatch`
  - 材料批次，表示一批泥浆、釉料、色釉或其他生产材料。
- `MaterialTestRecord`
  - 材料检测记录，记录含水率、流动性、粘度、比重、颜色、杂质、试烧等测试结果。
- `MaterialUsageRecord`
  - 材料使用事实，记录某批材料实际被用于哪个在制品、工序批次或生产任务。
- `MaterialQualityFlag`
  - 材料风险标记，记录某批材料后续被发现存在风险、限制使用或停用。

### 11.3 MES 第一阶段负责

- 泥浆批次最小建档
- 釉料/色釉批次最小建档
- 常用测试数据摘要录入
- 成型时绑定泥浆批次
- 喷釉时绑定釉料/色釉批次
- 质检时可反查材料批次
- 材料批次风险标记
- 支持按材料批次统计不良率

### 11.4 第一阶段不负责

- 完整材料配方管理
- 完整实验室 LIMS
- 自动供应商评分
- 复杂材料成本核算
- 长期材料质量治理体系

### 11.5 与质量瑕疵的关系

质检发现瑕疵时，系统应能从瑕疵记录反查：

- 该产品使用的泥浆批次
- 该产品使用的釉料/色釉批次
- 这些批次的测试数据摘要
- 这些批次是否存在风险标记
- 同批材料是否在其他产品上出现类似瑕疵

当前推荐结论：

- `mes-service` 第一阶段拥有材料使用事实。
- 完整材料标准、配方、实验室与供应商评估后续可进入独立主数据/质量/SRM 设计。
