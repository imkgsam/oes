## 2. 当前设计范围

本轮 WMS 设计已经覆盖：

- 基于真实现场场景定义 WMS 的价值主线，而不是先从抽象模块命名出发。
- 明确 WMS 第一阶段首先服务“库存准确闭环”，而不是先追求复杂自动化策略。
- 明确 WMS 与 `mes-service`、未来 `ERP.sales / fulfillment`、扫码平台之间的责任边界。
- 明确混合库存现实：
  - 无码按数量管理
  - 箱码管理
  - 单件码管理
  - 条码渐进上线
  - 箱 / 件 / 套等单位换算
- 明确多仓与多库存类型现实：
  - 配件仓
  - 包装耗材仓
  - 空瓷仓
  - 成品仓
  - 原料仓
  - 模具相关库存
  - 多个同类仓并存
- 明确包装、后处理、试水、返修、冻结、占用与紧急订单重分配等关键场景。

本轮刻意不继续冻结：

- 正式 gRPC / HTTP 契约字段。
- 正式 Prisma schema、表结构与索引策略。
- 原料仓是否全部纳入 WMS 第一阶段。
- 模具库存应主要归 WMS 还是未来资产 / 工装能力。
- 波次、补货策略、库位优化算法等高级策略能力。

## 3. 业务现场与关键使用场景

### 3.1 现场现实

当前业务现场不是标准化单一货架仓，而是混合仓储现实：

- 卫浴陶瓷大件重、不规则、存在倒塌风险，不能默认按标准货架仓思路设计。
- 配件更适合箱 / 件 / 货架式管理。
- 陶瓷体、空瓷与成品更适合区位管理，并要求准确记录入库位置。
- 不同仓库、不同区域对库存对象的管理方式可能不同。
- 并非所有库存天然有条码，系统必须允许无码起步，再逐步接入箱码或单件码。

### 3.2 已确认高价值场景

本轮已确认以下场景对 WMS 有明确价值：

- `MES -> WMS` 交仓
  - 产品烧成完成后，不会自动进入仓库管理。
  - 必须经过特定质检 / 确认节点，允许交仓后，WMS 才正式接手。
- 区位管理与查库取货
  - 对陶瓷类库存，重点不是货架优化，而是准确记录“货在哪个仓、哪个区位”。
- 库内调拨与跨仓调拨
  - 这是库存准确的基础能力，不是后期优化项。
- 出货前冻结 / 受限管理
  - 防止瑕疵品、待处理品、待确认品误发。
- 出货流程简化
  - 前提是先保证准确，再尽量减少不必要工作量。
- 包装作业
  - 包装属于库存转换与出货准备的重要环节。
- 后处理协同
  - 打孔、laser logo、修补、试水等场景在出货前真实存在，且并不总在标准生产线内完成。
- 混合追踪
  - 既要支持一物一码，也要支持按数量追踪。

### 3.3 已确认的现场复杂性

- 空瓷既存在 `MES` 的生产缓冲区，也存在 `WMS` 的正式库存区。
- 有些后处理在库存旁边直接完成，有些需要跨仓送指定测试区，有些需要外发加工。
- 紧急订单场景下，可能需要查看：
  - 现成目标 SKU 库存
  - 可转化基础 SKU 库存
  - 已包装但可拆包重配的库存
  - 已占用但尚未出货、允许经人工审批重分配的库存

## 5. WMS 的推荐定位

`wms-service` 在 OES 中的推荐定位是：

- 统一的仓储执行与库存真相服务。
- 负责回答“货现在在哪里、还有多少、处于什么状态、能不能再被别人使用、下一步仓内应该怎么处理”。
- 长期承接库存责任、仓储执行、占用控制、位置管理、包装准备、冻结控制与出货前仓储闭环。

它不是：

- 制造工序真相服务。
- 质量判定真相服务。
- 订单与经营承诺真相服务。
- 条码平台或扫码平台真相服务。

## 6. WMS 拥有与不拥有的内容

### 6.1 WMS Owns

- 仓库、仓区、区位、缓冲区、待处理区、待发区等仓储拓扑。
- 正式仓储责任下的库存对象与库存余额真相。
- 入库、上架、区位记录、移位、调拨、跨仓流转。
- 库存状态管理：
  - 可用
  - 冻结
  - 待处理
  - 受限
  - 已包装
  - 待发
  - 已占用
- 包装作业与包装耗材领用引起的库存转换。
- 占用 / 预留 / 分配真相。
- 后处理前的锁定、送处理、回仓、失败转受限等仓储侧动作。
- 盘点差异发现与库存动作历史查询。
- 混合追踪模式：
  - 无码按数量
  - 箱码
  - 单件码

### 6.2 WMS Does Not Own

- 胚体与制造过程中的 WIP 真相。
- 打孔、laser logo、修补、试水等后处理工序执行真相。
- 质检规则、质量放行规则与质量结论真相。
- 销售订单、交期承诺、经营单据与财务真相。
- 扫码解析平台真相。

## 7. 推荐边界判断口径

判断一个对象归 `MES` 还是 `WMS`，不应只看它是不是实物，而应看它当前属于哪段责任链：

- 如果它仍属于制造过程责任，主要为了完成下一道生产 / 质检 / 返修工序而存在，则归 `MES`。
- 如果它已经进入正式仓储责任，需要按库存去管理位置、数量、状态、占用、冻结、调拨、包装或待发，则归 `WMS`。

因此：

- 生产中的胚体、车间内部待检 / 待修 / 待烧对象，归 `MES`。
- 正式库存区中的配件、包装耗材、空瓷库存、成品库存，归 `WMS`。
- 空瓷是否归 WMS，不由名称决定，而由是否已经完成放行并进入正式库存区决定。

## 8. 核心业务规则草稿

### 8.1 交仓规则

- 烧成完成不等于入库。
- 只有在完成特定质检 / 确认并允许交仓后，WMS 才能创建自己的库存对象并接手责任。
- `MES -> WMS` 的本质是责任转移，而不是对象搬家。

### 8.2 占用规则

- 占用真相唯一来源于 WMS。
- ERP 提供订单承诺或履约需求。
- WMS 根据位置、数量、状态、单位、冻结与已占用情况决定是否能占用及占用哪批库存。
- 紧急订单允许重分配已占用库存，但必须经过人工审批。

### 8.3 履约可用性判断规则

当订单要求某目标 SKU 时，系统判断优先级应为：

1. 先看目标 SKU 的现货库存。
2. 若没有，再看是否存在可转化为目标 SKU 的基础 SKU 库存。
3. 对于紧急订单，可进一步查看：
   - 已包装但允许拆包重配的库存
   - 已被其他订单占用、但尚未出货且经人工审批可重分配的库存

### 8.4 包装规则

- 包装作业系统上归 WMS。
- 包装不是纯记录动作，而是“空瓷 / 中间库存 + 包材 -> 可发货成品库存”的库存转换过程。
- 包装工人组织归属暂不冻结，但不影响包装作业归 WMS 的系统边界。

### 8.5 后处理规则

以下动作原则上归 `MES`：

- 钻孔
- laser logo
- 修补
- 试水

WMS 在这些场景中负责：

- 将库存送入后处理前的锁定 / 冻结
- 跨区、跨仓或外发的仓储流转
- 处理返回后的回仓
- 合格、受限、返修、报废等库存状态变化

### 8.6 盘点规则

- 盘点本身主要用于发现差异，不负责自动解释差异根因。
- 真正帮助排查原因的是库存动作历史，而不是盘点动作本身。

## 9. 推荐能力分组

本轮讨论后，WMS 推荐至少具备以下能力分组：

- `warehouse-topology`
  - 仓库、仓区、区位、缓冲区、待发区、待处理区
- `inventory`
  - 库存对象、库存余额、状态、位置、单位换算
- `inbound`
  - 入仓接手、入库登记、上架 / 入区位
- `movement`
  - 库内移位、跨仓调拨、送后处理、外发、回仓
- `reservation`
  - 占用、释放、重分配审批
- `packaging`
  - 包装作业、包材消耗、成品转换
- `outbound`
  - 出货前准备、待发、发运扣减
- `traceability`
  - 无码 / 箱码 / 单件码并存的追踪能力
- `audit-history`
  - 库存动作历史与差异排查入口

## 10. 当前推荐的协同口径

### 10.1 与 MES

- MES 负责制造对象、后处理工序、试水与质量相关执行真相。
- WMS 负责正式库存责任、送处理、回仓与库存状态控制。
- 对于空瓷等边界对象，应通过明确的放行 / 交仓条件切换责任。

### 10.2 与 ERP / Fulfillment

- ERP 负责订单承诺、履约优先级与人工审批语义。
- WMS 负责实际库存可用性、占用、释放、重分配与出货前仓储动作。
- ERP 不应维护一套独立的物理占用真相。

### 10.3 与扫码平台

- 扫码平台负责统一编码、解析与路由。
- WMS 负责被路由到自己之后的仓储业务语义。

## 11. 第一阶段优先闭环

基于当前场景判断，WMS 第一阶段最值得优先闭环的能力是：

- 放行后交仓
- 区位管理
- 入库位置记录
- 库内移位与跨仓调拨
- 状态准确与冻结控制
- 单位换算一致性
- 占用真相与人工审批重分配
- 包装转换
- 送后处理 / 回仓
- 出货前的准确控制

第一阶段不必优先做重：

- 高级库位优化算法
- 重型波次与复杂自动补货策略
- 假设全仓天然一物一码
- 以标准货架仓为中心的设计
