# PolicyInstance Management Contract

> 服务设计唯一真相源：[permission-service.md](../../architecture/services/permission-service.md)。本文只描述 `PolicyInstance` 管理契约，不重新定义资源授权模型、组合规则或业务资源 owner。

## 1. Purpose

This contract exposes controlled management queries and first-stage mutations for template-based `PolicyInstance` facts.

It exists to separate the new resource authorization mainline from legacy `Policy + conditionAstJson` governance.

## 2. Current Exposure Status

Current gRPC source:

- [policy_instance_management.proto](../../../src/common/src/contracts/permission_service/policy_instance_management.proto)

Exposed methods:

- `PolicyInstanceManagementService.CreatePolicyInstance`
- `PolicyInstanceManagementService.GetPolicyInstance`
- `PolicyInstanceManagementService.ListPolicyInstances`
- `PolicyInstanceManagementService.SetPolicyInstanceEnabled`

Current scope:

- List / detail governance.
- Create one template-based `PolicyInstance`.
- Enable / disable one persisted `PolicyInstance`.
- Requires policy management read permission for queries.
- Requires policy create / update permission for mutations.
- Does not expose legacy `conditionAstJson`.
- Does not expose free-form `params`; params are validated by built-in template schema.
- Does not yet expose full metadata update.

## 3. CreatePolicyInstance

Request fields:

```text
tenantId
subjectSelector
permissionCode
resourceType?
templateCode
effect
params
enabled?
priority?
```

Response:

```text
CreatePolicyInstanceResponse
```

Stable rules:

- Creates a `PolicyInstance` fact, not a legacy `Policy` row.
- `createdBy` and `updatedBy` are derived from authenticated operator context.
- `createdAt` and `updatedAt` are generated by permission-service.
- `enabled` defaults to true when omitted.
- `params` must match the built-in `PolicyTemplate` params schema.
- This mutation does not validate business resource existence; WMS / MES / CRM / SRM / Procurement remain resource fact owners.

## 4. ListPolicyInstances

Request filters:

```text
page
pageSize
tenantId?
permissionCode?
resourceType?
templateCode?
hasEnabledFilter?
enabled?
```

Response:

```text
policyInstances[]
total
page
pageSize
```

Stable rules:

- Returned records are `PolicyInstance` records, not legacy `Policy` records.
- `params` shape remains template-controlled; callers must not treat it as free-form AST.
- `hasEnabledFilter` distinguishes “do not filter enabled state” from `enabled = false`.

## 5. GetPolicyInstance

Request:

```text
id
```

Response:

```text
GetPolicyInstanceResponse
```

Stable rules:

- The response includes subject selector, permission code, resource type, template code, effect, validated params, enabled state, priority, and audit timestamps.
- Business resource master data is not returned by this contract.

## 6. SetPolicyInstanceEnabled

Request:

```text
id
enabled
```

Response:

```text
SetPolicyInstanceEnabledResponse
```

Stable rules:

- Only changes enabled state and update audit metadata.
- Does not change `subjectSelector`, `permissionCode`, `resourceType`, `templateCode`, `effect`, or `params`.
- Does not delete the `PolicyInstance`.
- Does not touch legacy `Policy + conditionAstJson`.

## 7. Remaining Mutation Boundary

Full metadata update is intentionally not part of this first mutation contract.

Before broader update APIs are opened, the implementation must freeze:

- Idempotency semantics.
- Partial update field presence semantics.
- Whether `priority`, `effect`, `subjectSelector`, or `params` are mutable after creation.
- Compatibility policy for existing preview and first-stage create UI.
