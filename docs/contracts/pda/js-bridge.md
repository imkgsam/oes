# PDA JS Bridge Contract

> PDA JS Bridge 不拥有 Terminal Access Policy、access summary、Role、Policy 或授权判定真相；这些服务设计边界以 [permission-service.md](../../architecture/services/permission-service.md) 为准。

## 1. Purpose

This document defines the Phase 1 PDA JS Bridge contract between Android Shell and Vue3 PDA Web.

The JS Bridge is a cross-device PDA capability contract. It is not a Dongji / Seuic Cruise Ge-specific API.

Its goal is to let Vue3 consume stable PDA capabilities while Android Shell adapts concrete device vendors, scanner SDKs, broadcast formats, WebView details, and Android APIs internally.

## 2. Core Decision

PDA Web must depend on OES PDA capabilities, not on a specific hardware vendor.

Rules:

- Vue3 must not call manufacturer SDKs directly.
- Vue3 must not depend on Dongji / Seuic Cruise Ge field names.
- Android Shell owns vendor-specific adaptation.
- Android Shell normalizes device capability output into this contract.
- Future PDA models should be integrated by changing Android Shell adapters first, not by rewriting PDA Web pages.

## 3. Communication Model

The Bridge uses two interaction styles:

- command call: Vue3 asks Android Shell to do something
- event push: Android Shell notifies Vue3 that something happened

Examples:

- command call: Vue3 calls `openCamera`, Android Shell opens camera and returns photo metadata.
- event push: Android Shell receives a scanner result and pushes `scanResult` to Vue3.

## 4. Common Command Result

All Bridge commands return the same envelope.

Success:

```json
{
  "ok": true,
  "data": {},
  "error": null
}
```

Failure:

```json
{
  "ok": false,
  "data": null,
  "error": {
    "code": "CAMERA_PERMISSION_DENIED",
    "message": "Camera permission denied"
  }
}
```

Rules:

- Commands must be asynchronous from Vue3's point of view.
- `error.code` must be stable enough for UI and diagnostics.
- `error.message` is diagnostic text, not a long-term business semantic.

## 5. Common Event Envelope

All pushed events use the same envelope.

```json
{
  "eventId": "evt_001",
  "eventType": "scanResult",
  "occurredAt": "2026-05-13T10:20:00Z",
  "payload": {}
}
```

Rules:

- `eventId` is generated by Android Shell for diagnostics and deduplication.
- `eventType` identifies the event kind.
- `occurredAt` is Android Shell's event time.
- `payload` is event-specific.

## 6. Commands

### 6.1 `getDeviceInfo`

Returns normalized PDA device and App information.

Request:

```json
{}
```

Response `data`:

```json
{
  "deviceId": "SEUIC-SN-123456",
  "idSource": "MANUFACTURER_SERIAL",
  "fallbackAppDeviceId": "app-uuid-xxx",
  "vendor": "SEUIC",
  "manufacturer": "Seuic",
  "model": "Cruise Ge",
  "androidVersion": "9",
  "appVersion": "1.0.0",
  "capabilities": {
    "scanner": true,
    "camera": true,
    "nfc": false,
    "bluetoothPrinter": false,
    "foregroundService": false
  },
  "scanner": {
    "provider": "MANUFACTURER_BROADCAST",
    "sources": ["BROADCAST"]
  }
}
```

`idSource` values:

| Value | Meaning |
| --- | --- |
| `MANUFACTURER_SERIAL` | Device id was read from a stable manufacturer / Android device identifier. |
| `APP_GENERATED` | Device id was generated by OES PDA App because manufacturer id was unavailable or unreliable. |

Capability rules:

- `capabilities` describes what the current device / Shell implementation can support.
- Vue3 may hide or disable diagnostic cards when a capability is unavailable.
- Unsupported Phase 1 capabilities should return `false`, not be omitted.

### 6.2 `getNetworkStatus`

Returns the current network state observed by Android Shell.

Request:

```json
{}
```

Response `data`:

```json
{
  "networkStatus": "ONLINE",
  "networkType": "WIFI"
}
```

`networkStatus` values:

- `ONLINE`
- `OFFLINE`
- `UNKNOWN`

`networkType` values:

- `WIFI`
- `CELLULAR`
- `ETHERNET`
- `NONE`
- `UNKNOWN`

### 6.3 `openCamera`

Opens camera and returns local photo metadata after capture.

Request:

```json
{
  "maxCount": 1,
  "quality": "COMPRESSED"
}
```

Response `data`:

```json
{
  "localUri": "content://oes-pda/photos/photo_001.jpg",
  "fileName": "photo_20260513_102000.jpg",
  "mimeType": "image/jpeg",
  "sizeBytes": 382122,
  "width": 1280,
  "height": 960
}
```

Phase 1 rules:

- Only camera capture is required.
- Gallery picking is not required.
- Photo upload is not part of this contract.
- Android Shell may compress photos before returning metadata.

### 6.4 `openCameraScanner`

Opens a native live camera scanner and returns immediately after Android accepts the request. A successful decode is pushed back to Vue3 through the existing `scanResult` event.

Request:

```json
{
  "formats": ["QR_CODE", "CODE128"]
}
```

Response `data`:

```json
{
  "accepted": true
}
```

Rules:

- The Android Shell owns camera permission, preview, decode loop, cancellation, and camera lifecycle.
- Android Shell must decode only the configured first-phase formats: `QR_CODE` and `CODE128`.
- Android Shell must not infer WMS / MES / HR / enrollment business meaning from the decoded value.
- Vue3 must consume successful camera scans through the same `scanResult` event used by hardware scanners.
- If the operator cancels, Android Shell returns or logs a stable cancellation result without creating a `scanResult`.
- This command is separate from `openCamera`; photo capture and camera scanning are different device capabilities.

### 6.5 `vibrate`

Triggers device vibration feedback.

Request:

```json
{
  "durationMs": 120
}
```

Response `data`:

```json
{
  "triggered": true
}
```

### 6.6 `beep`

Triggers device sound feedback.

Request:

```json
{
  "type": "SUCCESS"
}
```

Response `data`:

```json
{
  "triggered": true
}
```

`type` values:

- `SUCCESS`
- `ERROR`
- `WARNING`

### 6.7 `saveRefreshToken`

Stores refresh token in Android Shell secure storage.

Request:

```json
{
  "refreshToken": "jwt-refresh",
  "sessionId": "sess_001"
}
```

Response `data`:

```json
{
  "saved": true
}
```

Rules:

- Vue3 must not persist refresh token in localStorage.
- Android Shell owns refresh token persistence.
- The Bridge must never expose refresh token through logs.

### 6.8 `getAccessTokenByRefresh`

Uses the stored refresh token to request or return a fresh access token.

Request:

```json
{}
```

Response `data`:

```json
{
  "accessToken": "jwt-access",
  "expiresAt": "2026-05-13T10:30:00Z",
  "sessionId": "sess_001"
}
```

Rules:

- If refresh fails, Android Shell should clear stored session data and return a stable error.
- Terminal Access Policy and session validity remain backend-owned.

### 6.9 `clearSession`

Clears Shell-owned session data.

Request:

```json
{
  "reason": "LOGOUT"
}
```

Response `data`:

```json
{
  "cleared": true
}
```

`reason` examples:

- `LOGOUT`
- `IDLE_TIMEOUT`
- `SESSION_EXPIRED`
- `DEVICE_DISABLED`

### 6.10 `writeLog`

Writes a local diagnostic log entry.

Request:

```json
{
  "level": "INFO",
  "eventType": "SCAN_RECEIVED",
  "message": "Scan result received",
  "diagnosticMode": true,
  "details": {
    "scanValue": "PB202605130001",
    "scanLength": 14,
    "scanSource": "BROADCAST"
  }
}
```

Response `data`:

```json
{
  "written": true
}
```

Rules:

- Logs must not include password, access token, refresh token, photo file content, or full business documents.
- Phase 1 manual diagnostic logs may include full `scanValue` when `diagnosticMode = true`.
- Future business logs must not automatically include full business scan values unless a user manually triggers diagnostic upload.

## 7. Events

### 7.1 `scanResult`

Pushed when Android Shell receives a scan result from the active scanner integration.

Event:

```json
{
  "eventId": "evt_001",
  "eventType": "scanResult",
  "occurredAt": "2026-05-13T10:20:00Z",
  "payload": {
    "scanValue": "PB202605130001",
    "scanSource": "BROADCAST",
    "scannerProvider": "MANUFACTURER_BROADCAST",
    "symbology": "CODE128",
    "rawLength": 14
  }
}
```

`scanSource` examples:

- `BROADCAST`
- `SDK`
- `KEYBOARD`
- `CAMERA`
- `UNKNOWN`

`scannerProvider` examples:

- `MANUFACTURER_BROADCAST`
- `MANUFACTURER_SDK`
- `ANDROID_CAMERA`
- `WEB_FALLBACK`
- `UNKNOWN`

Rules:

- Android Shell must not infer WMS / MES business meaning from `scanValue`.
- Vue3 Phase 1 only displays scan diagnostic data.
- Future business pages may interpret the scan value in page/application logic or call business BFFs.

### 7.2 `networkChanged`

Pushed when Android Shell observes a network state change.

Event:

```json
{
  "eventId": "evt_002",
  "eventType": "networkChanged",
  "occurredAt": "2026-05-13T10:21:00Z",
  "payload": {
    "networkStatus": "OFFLINE",
    "networkType": "NONE"
  }
}
```

### 7.3 `sessionCleared`

Pushed when Android Shell clears session data.

Event:

```json
{
  "eventId": "evt_003",
  "eventType": "sessionCleared",
  "occurredAt": "2026-05-13T10:22:00Z",
  "payload": {
    "reason": "IDLE_TIMEOUT"
  }
}
```

## 8. Error Codes

Recommended Phase 1 Bridge error codes:

| Code | Meaning |
| --- | --- |
| `BRIDGE_UNAVAILABLE` | Android Bridge is unavailable or not initialized. |
| `UNSUPPORTED_CAPABILITY` | Device or Shell does not support the requested capability. |
| `CAMERA_PERMISSION_DENIED` | Camera permission was denied. |
| `CAMERA_CAPTURE_CANCELLED` | User cancelled camera capture. |
| `CAMERA_CAPTURE_FAILED` | Camera capture failed. |
| `SECURE_STORAGE_FAILED` | Secure storage operation failed. |
| `REFRESH_TOKEN_MISSING` | No refresh token is available in Shell storage. |
| `REFRESH_SESSION_FAILED` | Refresh request failed or session is no longer valid. |
| `NETWORK_UNAVAILABLE` | Network is unavailable for the requested operation. |
| `UNKNOWN_ERROR` | Unexpected Shell-side failure. |

## 9. Security Rules

- Refresh token must be stored by Android Shell, not by Vue3 localStorage.
- Bridge logs must never include access token or refresh token.
- Bridge must not expose raw Android objects to Vue3 pages.
- Vue3 pages must use a typed `bridgeClient` wrapper.
- Android Shell must validate command names and payload shapes before executing.
- Unsupported capabilities must fail clearly with `UNSUPPORTED_CAPABILITY`.

## 10. Phase 1 Non-goals

- Bluetooth printing.
- NFC.
- Foreground service heartbeat.
- Boot auto-start.
- MDM integration.
- Hot update.
- Business scan parsing.
- Photo upload.
- Offline business queue.

## 11. Future Compatibility

When OES adopts newer PDA hardware:

- Android Shell should add or replace device adapters.
- The adapter should normalize hardware-specific scanner output into `scanResult`.
- The adapter should normalize hardware-specific device information into `getDeviceInfo`.
- Vue3 pages should remain stable unless a new capability is intentionally exposed.
- New hardware capabilities should first appear in `capabilities` before PDA Web starts depending on them.
